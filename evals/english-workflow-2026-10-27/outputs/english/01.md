**Summary**

QuantCache studies cached, quantized features for batch-one sensor classification on three datasets. Matched configurations evaluate caching and quantization separately. The manuscript reports lower CPU latency and small F1 differences, claiming at most .003 degradation in expected unseen-subject F1.

**Strengths**

1. The matched configurations distinguish caching from quantization: latency falls from 12.4 to 8.2 to 5.1 ms. Shared hardware and inclusion of preprocessing and cache lookup make this a useful system-level measurement.
2. The report exposes the practical tradeoff through the additional 28 MB memory requirement and explicitly distinguishes training-seed variability from uncertainty over new subjects.

**Weaknesses**

1. Section 2 selects each method's decision threshold by maximizing F1 on the same test labels used for reporting. This leaks evaluation labels into a pipeline decision, so the resulting F1 does not evaluate a fully frozen pipeline on unseen subjects. Subject-disjoint splitting and training-only feature learning do not resolve this issue. Select thresholds on validation data and report performance on an evaluation set untouched by selection.
2. The observed maximum .003 difference is not a bound on expected unseen-subject degradation. Even after correcting threshold selection, seed standard deviations alone cannot establish that bound. Qualify the conclusion as an observed difference unless appropriate evidence about subject-level uncertainty supports a stronger statement.

**Overall Assessment**

The latency improvement has credible, controlled support, but the central accuracy-preservation guarantee is unsupported. Substantial revision of the evaluation and conclusion is needed before acceptance; the reported speed benefit remains valuable.
